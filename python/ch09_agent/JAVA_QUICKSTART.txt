核心概念速记
---------------------------------
记忆三文件 = manifest.json（权威）+ MEMORY.md（目录）+ <name>-<id>.md（正文）

MemorySession 生命周期 = begin_turn → before_model → complete

三个无工具 side-query = selector（选择）+ extractor（提取）+ consolidator（整理）

文件事务模式 = 临时目录写入 → 原子 rename → manifest 最后更新

为什么需要 manifest.json = MEMORY.md 可以重建，manifest 是唯一权威指针

整理触发阈值 = 累积 5 条待处理记忆时自动合并去重

记忆注入方式 = 临时 system 消息（只影响当前请求，不进入 canonical history）


关键设计决策
---------------------------------
Q: 为什么 MEMORY.md 和 manifest.json 都要存在？
A: manifest 是事务权威（哪些记忆当前有效），MEMORY.md 是轻量目录（供选择器阅读），
   后者可以从前者重建，但分离后选择器不需要解析完整 JSON。

Q: 为什么记忆不是普通工具？
A: 如果模型能直接调用"写记忆"工具，会破坏事务一致性（写一半失败怎么办？）。
   用无工具 side-query + 受控的 MemoryStore 能保证原子性。

Q: 为什么记忆正文不直接追加到 canonical history？
A: 记忆是辅助上下文，不应污染对话历史。用临时注入的方式，下次回合自动消失。

Q: 为什么整理阈值是 5 条？
A: 太低频繁调用模型浪费成本；太高累积过多冗余记忆。5 是经验平衡值。

面试题速查（6 道）
---------------------------------
Q1: 第 9 章的记忆和第 8 章的压缩有什么区别？
A: 压缩是在当前会话内减少 token，记忆是跨会话保留知识。
   压缩丢失细节但保留对话脉络，记忆保留核心事实但不是完整对话。
   两者互补：压缩管"这次聊天"，记忆管"下次还要知道什么"。

Q2: 为什么 manifest.json 和 MEMORY.md 要分离？
A: manifest 是事务权威，记录当前有效的记忆集合（JSON 格式，易解析）。
   MEMORY.md 是轻量目录，供选择器快速扫描（Markdown 格式，模型友好）。
   MEMORY.md 可以从 manifest 重建，分离后选择器不需要解析完整 JSON。

Q3: 记忆的文件事务如何保证原子性？
A: 先写临时目录（所有 .md 文件），最后原子 rename 到目标路径。
   如果中途失败，临时目录会被丢弃，已有记忆不受影响。
   manifest.json 最后更新，确保指针和文件一致。

Q4: 为什么记忆不是模型可直接调用的普通工具？
A: 普通工具调用可能被拒绝、重试或部分执行，破坏事务一致性。
   用无工具 side-query（selector/extractor/consolidator）+ 受控 MemoryStore，
   能保证选择、提取、整理的逻辑由系统控制，模型只提供决策输入。

Q5: 记忆注入为什么用临时 system 消息而不是追加到 history？
A: 记忆是辅助上下文，不应污染 canonical history。
   临时注入只影响当前模型请求，下次回合自动消失。
   这样 history 保持对话真相，记忆作为背景知识按需加载。

Q6: 整理（consolidate）的触发时机和作用是什么？
A: 当累积 5 条待处理记忆时触发（可配置阈值）。
   作用：合并重复记忆、解决冲突、压缩冗余内容。
   模型输出 source_names（要替换的旧记忆）和 records（整理后的新记忆），
   系统删除旧文件，保存新文件，原子更新 manifest。
