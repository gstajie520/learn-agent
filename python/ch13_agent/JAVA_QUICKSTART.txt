---------------------------------
打开 features/background.py，按顺序阅读：
  1. BackgroundJob 数据类      → 状态快照（6 种状态）
  2. JobSupervisor.__init__     → 线程池初始化
  3. JobSupervisor.submit       → 提交任务到线程池
  4. JobSupervisor._worker      → 工作线程（超时检测、取消处理）
  5. JobSupervisor.close        → 优雅关闭（等待完成或中断）

重点理解：
  - threading.Thread = Thread
  - threading.Event = CountDownLatch（取消信号）
  - threading.RLock = ReentrantLock（可重入锁）
  - queue.Queue = BlockingQueue（线程安全队列）

核心概念速记
---------------------------------
后台任务 = submit 返回 job_id → worker 线程异步执行 → 终态发布事件 → 注入历史

状态机 = running（无 result）→ 终态（必须有 result）

工具分流 = dispatch 返回 None（同步）/ ToolResult（后台 job_id）

事件去重 = _seen_event_ids 防止重复注入同一事件

恢复机制 = 启动时 _recover，标记遗留 running 为 interrupted

面试常见问题速查
---------------------------------
Q: 为什么 dispatch 返回 None 表示继续同步执行？
A: 因为 ToolDispatcher 是可选策略层，None 表示"不处理，走默认流程"。
   只有返回 ToolResult 才短路后续 invoke。

Q: 后台任务的 6 种状态是什么？
A: running, completed, failed, timed_out, cancelled, interrupted
   running 不携带 result，其他终态必须携带 result。

Q: 为什么需要 source_tool_call_id？
A: 关联后台任务与原始工具调用，事件回填时模型可以追溯上下文。

Q: 并发容量如何控制？
A: JobSupervisor 维护 _controls 字典，submit 前检查 len(_controls) >= capacity。
   worker 完成后删除对应条目，释放槽位。

Q: 超时如何检测？
A: worker 循环每 0.1 秒检查 time.time() - start_time > timeout。
   超时时设置 cancel_event，标记为 timed_out。

Q: 为什么启动时要调用 _recover？
A: 上次进程可能异常退出，留下 running 孤儿任务。
   恢复时标记为 interrupted，发布事件通知模型。

Q: 原子写入如何实现？
A: 写临时文件 .tmp，成功后 rename 原子替换。
   rename 在多数文件系统上是原子操作。

Q: 事件去重机制？
A: 每个事件有唯一 event_id（UUID），AgentRunner 维护 _seen_event_ids。
   _inject_runtime_events 过滤已见事件。
