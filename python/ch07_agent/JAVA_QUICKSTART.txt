核心概念速记
---------------------------------
两级加载 = 扫描时只读 frontmatter（name + description）→ 使用时读完整正文

路径安全边界 = 名称校验 + 相对路径限制 + realpath 防符号链接逃逸

frontmatter = YAML 元数据（包裹在 --- 之间，必须包含 name 和 description）

TOCTOU 防御 = 扫描后符号链接可能被替换，加载时重新校验路径

为什么需要两级加载 = System Prompt 长度受限，几十个 Skill 全加载会超限

目录预算 = 最多 100 条、8000 字节，不截断半条目录行

常见问题（FAQ）
---------------------------------
Q1: 为什么扫描阶段不直接读取完整正文？
A: System Prompt 有长度限制，可能有几十个 Skill。启动时只给目录（名称+描述），
   模型判断需要哪个才调用 load_skill，节省 token 并提升响应速度。

Q2: 为什么加载时要重新校验路径？
A: 防止 TOCTOU 攻击。扫描时 skills/foo 可能指向安全目录，但攻击者可能在扫描后
   把符号链接改为指向 /etc/passwd。加载时重新 realpath 并判断仍在边界内。

Q3: Skill 名称为什么只允许 [a-z0-9-]？
A: 防止路径穿越。如果允许 ../secret 或 Windows 设备名（NUL、CON），攻击者可以
   构造恶意名称逃逸 workspace 边界或触发系统异常。

Q4: frontmatter 必须包含哪些字段？
A: name（等于目录名）和 description（单行描述）。name 用于路由，description
   放进 System Prompt 让模型判断何时需要这个 Skill。

Q5: 子 Agent 能调用 load_skill 吗？
A: 可以。bootstrap.py 中 child_tools_factory 为子 Agent 注册了 load_skill，
   但子 Agent 仍然没有 task 工具（不能再次委派子任务）。

Q6: 目录预算是什么？
A: 最多 100 条 Skill、8000 UTF-8 字节（可配置）。超出时截断，但不截断半条目录行，
   保证每条目录完整。按名称排序保证稳定。

Q7: SkillRegistry 是有状态的吗？
A: 扫描后是不可变的。scan() 返回的注册表包含元数据快照，load_skill() 不修改
   注册表状态，只是重新校验路径并读取文件。
