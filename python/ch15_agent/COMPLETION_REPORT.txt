核心概念速记
===============================================

四态状态机 = ready → processing → done / quarantine

message.id 三重身份 = 消息主键 + 事件去重 ID + 工具幂等键

ack-after-processing = 模型处理完成后才 ack，ack 失败保留租约只补确认

队友复用 = idle 状态保留 Runner 和历史，收到消息时唤醒

sender 来源保护 = 只能来自 ToolContext.identity，防止模型伪造身份

租约机制 = processing 状态即租约，只有持有者可 ack/release/quarantine


Ch15 与 Ch14 的主要差异
===============================================

| 维度 | Ch14 (Cron 事件) | Ch15 (持久队友) |
|------|------------------|-----------------|
| 核心能力 | 定时触发独立回合 | 多 Agent 可靠通信 |
| 新增边界 | CronJob/CronStore | MailboxMessage/MailboxStore/TeammateRuntime |
| 事件来源 | schedule_cron 工具 | spawn_teammate/send_message 工具 |
| 持久化 | state.json | 四态目录结构 |
| 身份模型 | 计划创建者身份 | 每个队友独立身份 + 独立历史 |
| 失败恢复 | durable outbox | recover_processing + quarantine |
