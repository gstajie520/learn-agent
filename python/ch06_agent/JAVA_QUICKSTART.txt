第 1 步：理解 TODO 跟踪器（10 分钟）
---------------------------------
打开 features/todos.py，理解 TODO 跟踪机制：
  核心类：TodoTracker（实现 ToolRoundObserver 协议）
  核心方法：observe_tool_round（每轮工具执行后回调）
  检测逻辑：_check_stale_plan（3 轮未更新触发提醒）

Java 类比：
  TodoTracker = @Component 实现 ToolRoundObserver 接口
  observe_tool_round = @EventListener 监听工具执行事件
  _snapshot = 快照对象记录当前计划状态

关键理解：
  - todo_write 时记录快照 + 重置计数器
  - 每轮 observe_tool_round 检查计数器
  - 达到 3 轮未更新时通过 Hook 注入提醒


第 2 步：理解子 Agent 机制（20 分钟）
---------------------------------
打开 features/subagents.py，按顺序阅读：
  1. SubagentTool.__init__  → 工厂注入（创建独立实例）
  2. task 工具定义          → 委派任务的接口
  3. handler 逻辑           → 创建隔离的 AgentRunner

重点理解父子 Agent 的隔离与共享：
  隔离：
    - 独立的消息历史（messages）
    - 独立的工具注册表（ToolRegistry）
    - 独立的 TODO 跟踪器（TodoTracker）

  共享：
    - HookRegistry（事件系统）
    - PermissionPolicy（权限策略）
    - workspace + identity（工作区和身份）

Java 类比：
  SubagentTool = @Service 委派服务
  ModelClientFactory = Supplier<ModelClient>
  ToolRegistryFactory = Supplier<ToolRegistry>
  父子隔离 = 每次 new AgentRunner(独立依赖)
  父子共享 = 构造时传入相同的 Hook/Policy 实例

核心概念速记
---------------------------------
TODO 快照 = todo_write 记录 + 每轮检查计数器 + 3 轮未更新触发 Hook

观察器协议 = ToolRoundObserver 接口 + observe_tool_round 回调

父子隔离 = 独立的历史/工具表/TODO 跟踪器（通过工厂创建）

父子共享 = 共享的 Hook/权限/工作区（构造时传入相同实例）

子 Agent 不能再委派 = system_prompt 禁止 + 保持任务边界清晰


常见问题速查
---------------------------------
Q: 为什么 TODO 过期阈值是 3 轮？
A: 经验值，太短容易误报，太长失去提醒意义。生产可配置。

Q: 子 Agent 的 max_turns 为什么是 30？
A: 子任务通常需要更多步骤，比父 Agent（20 轮）更宽松。

Q: 为什么需要 ModelClientFactory 而不是直接传 ModelClient？
A: 每次创建新实例，避免父子共享状态（如请求计数器）。

Q: 子 Agent 能访问父 Agent 的消息历史吗？
A: 不能，消息历史完全隔离，只能通过 task 参数传递上下文。

Q: 如何测试 TODO 过期逻辑？
A: 模拟 todo_write → 连续 3 次 observe_tool_round（不 write）→ 第 4 轮检查 Hook 提醒。

Q: 观察器协议的优势是什么？
A: 核心循环不感知 TODO 细节，符合开闭原则，易于扩展。
