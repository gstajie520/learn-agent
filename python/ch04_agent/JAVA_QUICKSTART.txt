第 3 步：理解权限与 Hook 协作（15 分钟）
---------------------------------
快速浏览两个文件，理解两层决策机制：
  - core/permissions.py → 系统级权限决策（四态：allow/deny/ask/passthrough）
  - core/loop.py        → Hook 在权限之后执行，但 Hook deny 会被尊重

权限与 Hook 的区别：
  权限层：系统级决策，deny 后直接跳过工具和 Hook
  Hook 层：业务扩展点，deny 后跳过工具但仍触发 PostToolUse

不要深入细节，知道有什么就行。


核心概念速记
---------------------------------
Hook 生命周期 = 四个固定事件（UserPromptSubmit → PreToolUse → PostToolUse → Stop）

tool_call_id 强配对 = 每个 tool_call 必须有且仅有一条 tool 消息（即使 deny/异常）

Hook 契约 = HookContext 字段按事件校验，HookResult 声明式影响，不直接修改状态

异步回调 = async def 回调自动识别，用 await 调用，类似 Java CompletableFuture

不可变数据流 = frozen dataclass + replace() 创建新对象，防止回调间相互影响

系统 deny 优先 = 权限 deny 后不触发 PreToolUse，Hook deny 后仍触发 PostToolUse

常见问题（FAQ）
---------------------------------
Q: Hook 和直接在循环里加 if/else 有什么区别？
A: Hook 是扩展点，新逻辑注册回调即可，不修改核心循环代码；
   if/else 会让循环越来越复杂，违反开闭原则。

Q: 为什么 Hook deny 后还要触发 PostToolUse？
A: PostToolUse 用于审计和日志，即使工具未执行也要记录"被阻止"事件；
   且 PostToolUse 看到的 result 是拒绝消息，可以追加审计信息。

Q: 同步和异步 Hook 可以混用吗？
A: 可以。HookRegistry 自动识别回调类型（inspect.iscoroutinefunction）；
   同步回调直接调用，异步回调用 await 调用。

Q: 如果 Hook 回调抛异常怎么办？
A: PreToolUse 异常时视为 deny，回填错误消息；
   PostToolUse 异常时保留原结果，记录 Hook 错误；
   Stop 异常不影响最终返回。

Q: 为什么需要 replace() 而不是直接修改字段？
A: frozen dataclass 字段不可变，replace() 创建新对象；
   确保每个回调看到一致的上下文，符合函数式编程原则。

Q: Hook 能修改消息历史吗？
A: 不能直接修改，但可以通过 append_messages 注入新消息；
   Stop Hook 可以追加总结消息到最终历史。

Q: 第三章的权限策略和第四章的 Hook 有什么关系？
A: 权限在前，Hook 在后；权限 deny 后不触发 PreToolUse；
   Hook deny 是业务逻辑层的阻断，权限 deny 是系统层的阻断。
