---------------------------------
打开 core/loop.py，找到 ToolRoundObserver 接口：
  - before_model() → 返回临时指导消息

    List<ChatMessage> beforeModel();

重点理解：
  - 观察器只能被动观察，不能修改或阻断

第 3 步：理解设计决策（15 分钟）
---------------------------------
思考以下问题，并在代码中找到答案：

Q1: 为什么 before_model 返回的消息不进 history？
A: 临时指导只对下次请求生效，持久化会污染长期历史并消耗 token。
   代码位置：loop.py:123 直接拼到 request，不 append 到 self._history

Q2: 为什么用完整快照而不是增量更新？
A: 避免实现 add/update/delete 三个接口，模型生成完整 JSON 更简单。
   代码位置：todos.py:98 直接替换 self._todos

Q3: 为什么计数器按工具轮而不是调用次数？
A: 一轮可能调用多个工具，按次数统计会误判。
   代码位置：loop.py:161-163 整轮结束后才调用一次 record_tool_round

Q4: 观察器和 Hook 有什么区别？
A: Hook 可以修改或阻断，观察器只能被动观察和记录。
   代码位置：loop.py:54-58 只读接口，没有返回 HookResult


核心概念速记
---------------------------------
观察器模式 = TodoTracker 观察工具轮结束事件，但不能修改执行流程

临时指导消息 = 只拼到本次 ModelRequest，不进入 history，下次自动消失

完整快照提交 = todo_write 要求提交全部任务，不支持增量修改

防抖机制 = 连续 3 轮未更新才提醒，避免每轮都骚扰模型

会话级状态 = TODO 只存在于当前 AgentRunner，销毁时自动消失


Java 开发者常见疑惑
---------------------------------
Q: TodoTracker 的状态为什么不持久化？
A: 第 5 章只演示会话级状态管理，持久化属于第 6+ 章内容。

Q: 为什么 _validate_todo_input 这么严格？
A: 拒绝未知字段（set(value) != {"todos"}）是防御式编程，
   避免模型生成的额外字段污染内部状态。

Q: before_model 能返回 assistant 消息吗？
A: 不能，只能返回 system 消息，避免伪造模型回答或工具结果。

Q: 为什么防抖是 3 轮不是 5 轮或 10 轮？
A: 经验值，平衡提醒及时性和骚扰度。可以通过 STALE_TOOL_ROUNDS 常量调整。
