核心概念速记
---------------------------------
原子认领机制 = BEGIN IMMEDIATE { 扫描 ready → 检查依赖 → 写入 owner/token/lease } COMMIT

租约到期回收 = 半开区间 [start, end) 到期后清空 owner/token，旧 token 仍无效

claim_token 防重 = UUID 一次性令牌，完成时必须匹配当前有效 token

队友优先级 = mailbox 优先 → protocol gate → 空闲 claim_next → idle 休眠

为何禁止 create_task = 防止空闲轮询无限扩张任务图，保证收敛

owner 身份绑定 = ToolContext.identity 不可伪造，类比 Spring Security principal


Python-Java 对照速查
---------------------------------
LeasedTaskStore Protocol = Repository<Task> interface
BEGIN IMMEDIATE = SELECT FOR UPDATE（悲观锁）
claim_token = 乐观锁版本号（防重复提交）
threading.Event = CountDownLatch（线程等待/唤醒）
threading.Lock = ReentrantLock（互斥锁）
executescript = batch update（批量 SQL）
cursor.fetchone = queryForObject（查询单行）
TeammateRuntime = WorkerService（工作者管理器）


面试题速查
---------------------------------
Q1: 为什么用 BEGIN IMMEDIATE 而非 BEGIN DEFERRED？
A: BEGIN IMMEDIATE 立即获取写锁，防止扫描和写入之间被插入。
   DEFERRED 可能导致两个 worker 同时扫描到同一个 ready 任务。
   类比 Java 的 SELECT FOR UPDATE。

Q2: 租约到期后为何旧 claim_token 仍无效？
A: claim_token 绑定到一次认领。过期回收清空 owner 和 token，
   新认领生成新 token。允许旧 token 会覆盖新 worker 进度。
   类比 JWT 过期后不能续期，只能重新登录。

Q3: 队友为何不能调用 create_task 工具？
A: 空闲轮询会让队友不断认领新任务。如果队友能创建任务，
   会无限扩张任务图，永远不会 idle。只有 Lead 能规划任务。

Q4: mailbox 优先级如何实现？
A: _run_worker 循环先检查 mailbox，有消息直接处理。
   没消息才检查 protocol gate，最后才尝试 claim_next。
   这是代码顺序保证的，不是配置项。

Q5: 空闲等待如何唤醒？
A: poll_wakeup 是 threading.Event，收到新消息调用 set() 唤醒。
   stop 信号也会唤醒。避免忙等浪费 CPU。
   类比 Java 的 Condition.await() + signalAll()。

Q6: 为何 owner 不能由模型填写？
A: owner 来自 ToolContext.identity，是框架注入的可信身份。
   让模型填写 owner 可能伪造身份，绕过权限检查。
   类比 Spring Security 的 @AuthenticationPrincipal。

Q7: SQLite 如何支持多个 worker 并发认领？
A: BEGIN IMMEDIATE 串行化写入，每个 worker 独立事务。
   SQLite 的 WAL 模式允许多读并发。认领失败重试下一个任务。
   类比数据库连接池 + 乐观锁重试。

Q8: 为何队友复用 AgentRunner 而非每次创建？
A: 历史保留上下文，模型能记住之前的对话。避免重复初始化。
   降低模型 token 成本（system prompt 只发一次）。
   idle 是"空闲等待"，不是"关闭销毁"。

常见错误排查
---------------------------------
错误 1：task_claim_mismatch
原因：owner 或 claim_token 不匹配
排查：检查 complete_task 传入的 claim_token 是否正确

错误 2：task_lease_expired
原因：租约已过期，任务回到 pending
排查：检查 lease_duration_seconds 是否过短

错误 3：task_blocked
原因：任务依赖未完成
排查：检查 blocked_by 列表中的任务状态

错误 4：database is locked
原因：SQLite 写锁超时
排查：检查是否有长事务未提交，考虑启用 WAL 模式
