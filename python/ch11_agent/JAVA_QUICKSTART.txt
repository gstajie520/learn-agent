第 1 步：从测试理解故障场景（10 分钟）
---------------------------------
打开 tests/test_recovery.py，理解三种故障：
  输入：ModelRequest（消息历史 + 工具定义）
  输出：ModelReply（可能成功、截断、过长、限流）
  恢复：RecoveryManager 内部重试，外层无感知

Java 类比：先读 ResilienceServiceTest 理解容错需求

三种故障类型：
  1. 输出截断：finish_reason == "length"
     → 第一次升级预算到 64000，第二次启动续写
  2. 输入过长：ModelPromptTooLongError
     → 保留 system，压缩历史，一次请求只压缩一次
  3. 临时故障：429（限流）/ 529（过载）
     → 指数退避 + Jitter，连续 3 次 529 切 fallback


第 2 步：读恢复管理器核心循环（20 分钟）
---------------------------------
打开 features/recovery.py，按顺序阅读：
  1. RecoveryConfig（不可变配置 record）
  2. RecoveryState（可变状态对象）
  3. RecoveryManager.complete()（主恢复循环）
  4. _retry_transient()（退避逻辑）

重点理解：
  - RecoveryManager = Resilience Service（Hystrix/Resilience4j）
  - CancellationToken = AtomicBoolean + 监听器集合
  - while True 循环 = 一次逻辑请求内部的多次物理重试
  - 外层 AgentRunner 只调用一次 executor.complete()

  - 第 1-10 章注入 raw model，第 11 章注入 RecoveryManager

核心概念速记
---------------------------------
恢复层本质 = 装饰器模式，包装 ModelClient，透明增加容错能力

三种故障恢复 = 输出截断（升级+续写）、输入过长（压缩）、临时故障（退避+切换）

为什么要归一化异常 = 核心层供应商无关，切换 API 只改适配器

指数退避 + Jitter = base * 2^attempt + random(0..upper)，避免惊群

Fallback 模型切换 = 连续 3 次 529 说明主模型持续不可用

CancellationToken 限制 = Python 同步 SDK 无法中止运行中请求，只能在边界检查

常见陷阱
---------------------------------
✗ 摘要请求套恢复层 → 会递归：输入过长→摘要→输入过长
  ✓ 摘要请求使用 raw ModelClient

✗ 单次 529 就切 fallback → 偶发性过载应该重试
  ✓ 连续 3 次 529 才切换

✗ 固定间隔重试 → 惊群效应，同时涌入
  ✓ 指数退避 + 随机 Jitter

✗ 外层历史包含续写消息 → 污染 canonical history
  ✓ 续写发生在局部 request_messages，成功后合并

✗ 无限重试 → 成本失控
  ✓ max_transient_attempts 和 total_timeout_seconds 双重保护


核心流程伪代码
---------------------------------
RecoveryManager.complete(request):
    state.current_max_tokens = 8000
    state.current_model = primary
    fragments = []

    while True:
        try:
            reply = model.complete(request with state)

            if reply.finish_reason == "length":
                if not state.has_escalated:
                    state.current_max_tokens = 64000  # 升级预算
                    continue
                else:
                    fragments.append(reply.content)   # 续写
                    request += (reply.message, user("Continue..."))
                    continue

            return merge_fragments(reply, fragments)

        except ModelRateLimitError as e:
            delay = parse_retry_after(e.retry_after) or backoff(attempt)
            sleep(delay)
            continue

        except ModelOverloadedError:
            state.consecutive_529 += 1
            if state.consecutive_529 >= 3:
                state.current_model = fallback  # 切换模型
            sleep(backoff(attempt))
            continue

        except ModelPromptTooLongError:
            leading_system, rest = split_messages(request)
            compressed = compaction.compact(rest)
            request = (leading_system, *compressed)
            continue


Java 对照速查
---------------------------------
RecoveryManager          = Hystrix / Resilience4j Service
CancellationToken        = AtomicBoolean + List<Runnable>
ModelRequestExecutor     = Strategy 接口
RecoveryConfig           = record（不可变配置）
RecoveryState            = POJO（可变状态）
_map_api_status_error    = Adapter 映射方法
指数退避                  = Exponential Backoff
Jitter                   = 随机抖动（避免 Thundering Herd）
